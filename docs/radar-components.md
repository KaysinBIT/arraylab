# 相控阵、雷达方程与脉冲雷达组件

0.26.0.dev0 将三个已完成的独立组件接入 ArrayLab 原生 Qt 工作台。原 WaveLab 1.4“雷达波形设计”保留；新增三个任务使用独立参数和结果，不启动原项目网页或服务。当前 GitHub 正式版仍为 0.25.0。

## 选择哪个任务

| 任务 | 用途 | 主要输出 |
| --- | --- | --- |
| 相控阵雷达设计 | 规则/自定义阵列分析、扫描范围、固定移相与真时延、线阵及二维稀疏综合 | 布局、实际馈相、切面、u-v 图、逐工况指标、优化结果 |
| 雷达方程验证 | 从输入功率/增益/噪声核算预算，再用独立接收处理链验证 | 预算与反算、距离–速度图、固定 CUT 的 SNR 对照、H0 校准、Pd/Pfa、距离统计、经验 ROC |
| 脉冲雷达设计 | 矩形、LFM、二相码、步进频；均匀/交错/多 PRF；相控、TDM、CDM | 回波/脉压、距离–速度与检测、角谱、模糊候选、三维场景、地形、反向设计候选 |

## 统一操作顺序

1. 左侧选择任务并展开。结果视图和参数分组都可直接定位；切换页面不启动计算。
2. 在右侧填写参数，或选择示例后点“载入示例”。频率、带宽、时间按字段标出的 GHz/MHz/μs 填写；文件内部仍保存原 SI 单位。目标、航迹、扫描工况用表格逐行编辑。
3. 在页面顶部选择操作，再按 F5。预算、回波仿真、统计和优化是不同操作，不会因打开配置自动连续执行。
4. 查看图形/表格。相控阵按所选工况联动切面、u-v 图、阵元馈相；脉冲场景的时间只控制真值预览，不能当作新的检测结果。
5. 保存参数供复算；保存完整记录保留已有数值；导出供外部查看或再打开。

一个后台任务运行时，其余模块 F5 和跨模块导入暂停。可取消计算和图形导出；取消或失败保留上次成功结果。完整记录写入为原子操作，写入开始后等待结束。三组件本版采用显式保存记录，未增加自动历史数据库，不改变直线阵和二维稀疏既有自动历史。

参数改动后，旧结果仍是上次成功计算的快照。保存参数会保存新输入；保存记录/导出仍保存该结果对应的输入，避免把未运行的新输入写成已验证结果。将优化候选应用到输入后，需要再次明确运行。

## 在现有模块间复用结果

- 雷达方程和脉冲页的“导入已算阵列”读取所选直线阵、二维稀疏、MIMO 物理 Tx/Rx 或相控阵的成功快照，分别导入 Tx 或 Rx。无可用来源时相应菜单置灰。
- 原阵列采用 x-y 孔径、+z 法线；新雷达采用 x 前向、y 左向、z 向上。导入将米制坐标 `(x,y,z)` 映射为 `(z,x,y)`，保持物理孔径。不会把旧扫描角、馈相、参考频率直接混入新模型；目标频率、指向和增益需在目标任务核对。
- 非各向同性单元不能直接导入。脉冲 1.0.1 只接受等幅通道；加权阵列明确拒绝，不悄悄抹掉幅度。SIMO、多通道上限和编码周期也按目标组件检查。
- 雷达方程的“导入已算 FMCW 波形”读取 WaveLab 当前所选 A/B 组。单组和分块 A/B 可导入；交替 A/B 不能等效成独立均匀组，明确拒绝。不会把两组能量相加。全 ramp 中心频率与 ADC 中心频率区别会在导入提示中注明。
- 相控阵“将所选工况送入平面馈电”保留物理坐标、幅度及该工况实际馈相，进入平面馈电后再按 F5。它不会把原来的相位量化效果再次量化。
- 导入新阵列或波形后，旧 H0 校准指纹不再有效；需按新配置重新校准。应用校准仅表示门限估计可用，不代表独立 Pd/Pfa 验收已通过。

## 文件与无头运行

| 文件 | 内容与打开方式 |
| --- | --- |
| 当前参数 JSON | 原始输入和操作选择；在对应任务“打开参数” |
| Pulse `.prlab` | 便携脉冲工程，包含导入 DEM；在脉冲页打开 |
| 完整记录 `.npz` | 输入、结果、原始数值数组、工况/视图/场景时间；顶部“打开记录”自动进入所属任务 |
| 导出文件夹 | 各组件 CSV/HTML/JSON、PNG、单份 `arrays.npz`、`arraylab-record.json`；通过后者恢复完整结果 |

导出文件夹中的记录与数组有摘要校验，应一起保存。多工况相控阵分别导出 `elements-case-N.csv`；`selected-view.csv` 和 `export-view.json` 记录当前选中内容。输出目录已存在时拒绝覆盖。旧版本不认识新增的三组件记录格式，旧模块的文件格式与历史路径不变。

```powershell
# 源码安装：完整桌面 + 地形读入；不使用地形时 radar extra 可省略。
.\.venv\Scripts\python.exe -m pip install ".[desktop,radar]"
.\.venv\Scripts\python.exe -m arraylab --headless phased --config examples/phased-uniform-linear.json --action analysis --output-dir results/phased01 --plot
.\.venv\Scripts\python.exe -m arraylab --headless equation --config examples/equation-01-fmcw-77-reference.json --action simulation --output-dir results/equation01 --workers 2 --plot
.\.venv\Scripts\python.exe -m arraylab --headless pulse --config examples/pulse-baseline.json --action simulate --output-dir results/pulse01 --workers 2 --plot
```

便携包使用同目录 `ArrayLab-cli.exe phased/equation/pulse ...`，无需 Python、Node 或原项目服务。无头计算不导入 Qt；PNG 导出需要 Matplotlib，已包含在便携包。

## 数值与资源边界

- 三组件沿用各自的电气/信号模型。公共化的是参数表单、任务调度、结果存取、导出、绘图容器与跨模块输入桥接。雷达方程参考预算与实际接收链保持独立，不能用同一公式相互“验证”。
- 数字波束、方向性、孔径和物理通道数不等于真实硬件增益、RF 链数或实测分辨率。导入不自动推定天线增益。
- 相控阵综合为有限候选/迭代及采样复核；未找到可行解不代表数学上不存在。固定移相和真时延按各自模型分析；未加入互耦、极化或全波计算。
- 脉冲场景输入真值用于生成数据及事后评价。普通 LFM 距离保留零多普勒匹配滤波表观距离；非均匀时序、步进频、TDM/CDM 的适用条件沿用来源组件。地形 NoData、网格外视线和未知高程基准不伪装成已知。
- 小样本 Pd/Pfa 统计不证明极低虚警率；零计数仍有非零置信上界。未将天线误差统计专题纳入本次功能。
- 后台计算和 PNG 导出在受管子进程中执行，Windows Job 负责内存预算、取消及子进程回收。结果数组读写放在后台线程，避免大文件堵住界面。
- 相控阵使用已有有界并行机制；雷达方程/脉冲限制 BLAS/FFT 线程数，保持试验及随机流顺序。自动模式依据工作量选择，显式支持单核或 2–8 路；不保证每种算法线性提速。保留来源组件的样本、通道、网格和内存限制。
- 本次实际环境是本机 Windows 10、Python 3.14.2；不宣称完成干净系统或硬件验收。物理馈线尺寸继续暂缓。

ArrayStudio 的 JavaScript 数值实现迁为 Python/NumPy，并与原实现做交叉对照。EquationLab 与 PulseLab 复用 Python 科学内核，调整包内导入及运行适配；不随包引入原 FastAPI/Web 服务。来源原生网页不等于 ArrayLab 集成验收，二者证据分别记录。

结构为 `features/phased`、`features/equation`、`features/pulse`，每个目录包含自身模型、计算、呈现、文件接口及测试。`application/simulation.py` 组装三组件，`application/bridges/radar.py` 管理跨模块转换；`framework/process.py` 复用受管进程，`shared/simulation_io.py` 复用数值记录，`shared/qt/configuration_form.py` 复用原生表单。基础层不导入具体业务。
