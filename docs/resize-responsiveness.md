# 分隔线拖动与图表重绘

0.25.0.dev4修复拖动“选择任务”与结果区之间的分隔线时明显卡顿的问题。原先每次Qt尺寸变化都会触发Matplotlib完整排版/绘制，雷达页的60毫秒延迟布局还可能再次绘制。同一段拖动会累积多个昂贵的完整帧。

现在桌面画布在连续尺寸变化期间缩放最后一张已绘制画面作为临时预览，停止变化约120毫秒后，按最终尺寸与屏幕像素比例重新排版和完整绘制。窗口大小、另一侧参数栏及使用同一画布的其他图形也采用这一处理。临时预览可能略模糊，最终图表恢复正常清晰度。

数值数组、阵列/波形计算结果、三维相机和二维缩放范围保持不变。保存图片、复制图片、显式绘制以及在图上开始鼠标操作会先结束尺寸预览；PNG按指定分辨率完整渲染，不导出拉伸的缓存图。视图隐藏或关闭会释放预览、停止延迟任务。

本机同一4Tx/4Rx、512 Chirp波形时序场景，offscreen Qt事件测试实际拖动左侧Dock从190到350像素，共40步：修改前完整绘制60次（59次发生于拖动中），拖动调用合计约9.60秒；修改后拖动期间0次、结束后1次，合计约0.16秒，单步中位耗时从约239毫秒降至约3.7毫秒。该计时是同一Qt测试路径，不是所有电脑或所有图形的帧率保证；最终完整帧绘制时间仍单独存在。

最终独立Windows程序另在已显示的原生窗口上验证：100%缩放下40步约0.213秒，125%下约0.245秒；两者均为拖动中0次完整绘制、停止后1次。两组各31项专项通过，数据、相机/缩放、最终排版和图片输出同时核对。

验收入口为`--smoke-suite resize`，只核对分隔线、临时预览、最终排版、截图导出及其他模块的画布接线。其他模块采用合成曲线检查容器行为，不冒充其数值算法验收。源码性能记录位于`tmp/resize-before`、`tmp/resize-after`及`tmp/resize-source`。
