# 分析方案格式（版本1）

这是ArrayLab新增的研制功能，不表示参考说明书已明确提供同名方案格式或项目持久化能力。方案用于恢复计算输入，并供桌面和无头入口共用。

## 文件结构

UTF-8 JSON，可带UTF-8 BOM，文件上限1 MiB。顶层必须且只能有以下3个字段：

```json
{
  "format": "arraylab.analysis",
  "schema_version": 1,
  "parameters": {
    "elements": 5,
    "frequency_ghz": 3.0,
    "spacing": 0.4,
    "spacing_unit": "lambda",
    "scan_deg": 60.0,
    "step_deg": 0.1
  }
}
```

`format`须精确匹配上述字符串；`schema_version`须为整数1。文件格式版本独立于应用版本0.4.0。`parameters`须完整包含6项参数，不能添加未知字段。

| 字段 | 类型与单位 | 范围/含义 |
| --- | --- | --- |
| elements | JSON整数 | 1–200 |
| frequency_ghz | 数值，GHz | 0.001–1000 |
| spacing | 数值 | 阵元中心间距，结合spacing_unit解释；折算后为0.000001–10λ |
| spacing_unit | 字符串 | `lambda`或`mm` |
| scan_deg | 数值，度 | −90至90；从+z朝+x为正，0代表正侧向 |
| step_deg | 数值，度 | 方向图采样步长0.01–5 |

所有数值必须有限。布尔值、数值字符串、null、NaN、Infinity、重复键均被拒绝。阵元数不接受5.0这种JSON浮点类型。范围为本软件输入约束，不能当作原软件说明书承诺。

## 兼容与运行

旧版平铺JSON继续可读，例如`{"elements":5,"spacing":0.4,"scan_deg":60}`。旧格式缺省项为：8阵元、3 GHz、0.5λ、扫描0°、步长0.1°；空对象也按该旧格式补默认值。新格式不补缺省字段，避免遗漏数据被静默解释。

桌面加载旧文件不会改写它；保存操作输出版本1。可另存新文件保留旧格式。所有加载先校验完整文件，再更新参数；错误文件不会局部修改桌面输入或历史结果。

CLI的`--config`接收两种格式。先校验配置文件，再应用显式命令行参数，最后校验合并结果；不能用命令行覆盖来隐藏本身无效的文件。CLI不会改写输入文件。参数错误退出码2，文件读取失败退出码3，错误细节写入标准错误JSON。

`summary.json`是计算结果报告，虽然也有`schema_version`与`parameters`字段，但不属于分析方案，不能直接作为`--config`输入。方向图DAT也不是方案。

## 桌面行为与保存边界

- 直线阵任务的“保存参数”读取当前输入；“导出所选曲线”读取所选历史结果，两者含义不同。
- 加载方案不计算、不清除曲线。图形和指标保留原结果；按F5后才形成新结果。
- 保存方案不包含历史曲线、导入文件、图形类型、显示下限、窗口布局或输出目录。
- 正侧向模式与扫描0°计算含义相同，加载scan_deg=0时统一显示为正侧向；不保存下拉框的冗余状态。
- 保存先校验，在目标文件同目录写临时文件，完成后原子替换；失败清理本次临时文件并保留已有目标内容。文件对话框负责已有文件覆盖确认。
- 无自动保存或退出提醒；关闭前按需要保存参数，或使用0.13.0的“保存记录”保留结果历史。后者是独立的[计算记录格式](calculation-history.md)，支持曲线、模型快照和所选项恢复；不是此处的参数文件。未知未来版本将拒绝加载，不进行猜测迁移。
